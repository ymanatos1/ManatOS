# Application and Platform Design

This area is for people designing business applications on the foundation rather than modifying the framework itself. It explains how product/domain concepts map onto Company, Platform, Application, canonical entities, metadata, expressions and reusable UI composition.

A useful reading order is:

1. [Platform Model](Platform-Model.md) — what a product/domain contribution owns;
2. [Application Model](Application-Model.md) — how first-class applications live inside a platform;
3. [Application Design Principles](Application-Design-Principles.md) — how to place rules and interaction at the correct semantic layer;
4. [Metadata-Driven Application Design](Metadata-Driven-Application-Design.md) — how canonical and UI metadata become application behavior;
5. [protoCRM](protocrm/README.md) — the current concrete platform and worked domain example.

The architecture and design folders remain authoritative for generic runtime semantics. Documents here restate enough of those concepts to make application design understandable on its own and link deeper when exact CTX, metadata, expression or security contracts matter.
